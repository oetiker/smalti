# Smalti 8x16 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `Smalti 8x16` at full parity with `Smalti 7x14` — four faces, all
1004 codepoints, its own green `make check`, both sizes in one `.deb` and one
`.rpm` — as release 0.2.0.

**Architecture:** The Makefile becomes a two-pass recursive make: with no
`SIZE` given it fans out over `SIZES`, and with `SIZE` given it is the existing
single-size Makefile unchanged.  The three 7x14-only generators gain 8x16
geometry beside their 7x14 geometry, never a scaled approximation.  The 309
hand drawings are produced in Unicode-block batches, each batch judged by the
implementer, then ruled on by the user against a new `make compare` chart.

**Tech Stack:** GNU make, Python 3 (project-local `.venv`, fontTools), BDF,
nfpm 2.47.0, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-25-8x16-design.md`

## Global Constraints

Copied from the spec and the project's standing rules.  Every task's
requirements implicitly include this section.

- **Never edit `upstream/`.**  It is pristine upstream BDF, kept for comparison.
  Adding the new `upstream/8x16/` directory is vendoring, not editing.
- **Never let one leg of `make check` answer to the name `check`.**  `check` is
  an umbrella over `check-sources`, `check-outlines` and `check-version`.
- **`check-packages` is deliberately NOT part of `check`.**
- **Nothing in packaging may be reachable from `make all` or `make check`.**
  The font build's dependency list is `python3-venv` and nothing else.
- **Nothing under `build/` is hand-editable**, including `build/gen/`.
- **The build must stay byte-reproducible.**  Anything that puts a clock or a
  hash seed into an artefact destroys the instrument that proves 7x14 was not
  perturbed.
- **One definition of the epoch.**  `FALLBACK_EPOCH` and `build_epoch()` live in
  `tools/glyphstore.py` and nowhere else.
- **`make -n` EXECUTES recipe lines containing `$(MAKE)`.**  This plan adds more
  of them.  Never dry-run a fan-out target.
- **The size is part of the family name** — `Smalti 8x16`, not `Smalti`.
- **Comments, names and technical docs in English.**
- **No `/tmp`.**  Use `/scratch/oetiker/claude-tmp/`.
- **Do not hand-edit the borrowed release files** beyond adding a publish job:
  `release-pr.yml`, `release-publish.yml`, `lib/*.js`, `.github/repo-infra.json`.
  `checks.js` and `release-pr.yml` carry `+ LOCAL PATCH` markers.
- **`finalize`'s `needs:` list in `release-publish.yml` is maintained BY HAND.**

### Task 2: Two-pass Makefile — fan out over sizes

**Files:**
- Modify: `Makefile:39` and the target list at `Makefile:76-80`

**Interfaces:**
- Consumes: `upstream/8x16/` from Task 1.
- Produces: `make <target>` fans out over `$(SIZES)`; `make SIZE=8x16 <target>`
  builds exactly one size.  Every later task relies on both forms.

**Approach:** wrap the existing body in `ifndef SIZE` / `else` / `endif`.  The
worker branch is the current Makefile with **no rule changed**, which is what
keeps this safe: 7x14 must build byte-identically afterwards.

- [ ] **Step 1: Record the byte-exact 7x14 baseline**

This is the instrument that proves the restructure changed nothing.

```bash
make clean && make all && sha256sum build/*.ttf | tee .superpowers/sdd/2026-08-25-8x16/7x14-before.sha256
```

- [ ] **Step 2: Add the dispatcher**

At the top of the Makefile, before any target:

```make
# Every size this repository builds.  With no SIZE on the command line the
# targets below re-enter make once per size; with SIZE set, this file is the
# single-size build it has always been.
SIZES := 7x14 8x16

# Targets that mean "do this for every size".  Targets that span sizes --
# packages, site, index, compare -- are NOT here; they run once and read all
# sizes themselves.
FANOUT := all check check-sources check-outlines check-version \
          outlines woff2 install preview show

ifndef SIZE
.PHONY: $(FANOUT)
$(FANOUT):
	@for s in $(SIZES); do \
	    echo "==> $@ [$$s]"; \
	    $(MAKE) --no-print-directory SIZE=$$s $@ || exit 1; \
	done
else
```

and `endif` at the very end of the file.  Change `SIZE := 7x14` to `SIZE ?= 7x14`
inside the worker branch — it is now always set by the dispatcher, and the
default only serves a direct `make SIZE=` invocation.

- [ ] **Step 3: Prove 7x14 is byte-identical**

```bash
make clean && make SIZE=7x14 all && sha256sum -c .superpowers/sdd/2026-08-25-8x16/7x14-before.sha256
```

Expected: four `OK` lines.  **Any mismatch means the restructure perturbed the
existing face — stop and find out why.**

- [ ] **Step 4: Prove the fan-out reaches both sizes**

```bash
make clean && make all
```

Expected: `==> all [7x14]` then `==> all [8x16]`.  The 8x16 pass **must fail**
at this point, in `gen-braille.py`, with `the dot geometry below is 7x14 only`.
That failure is the proof the fan-out works and the guards are intact.


### Task 3: Parameterise the emboldening width — and fix a silent 8-wide bug

**Files:**
- Modify: `tools/weight.py:21`, `tools/weight.py:51`
- Create: `tools/test-weight.py`

**Interfaces:**
- Consumes: nothing.
- Produces: `weight.set_width(w)` and `weight.widen(bm)` operating at the set
  width.  `tools/embolden.py` and `tools/slant-bold.py` both import this module.

**The bug.** `weight.py:51` ends `widen()` with `out.append(n & 0xFE)`.  At 7
wide, bit 0 is BDF row padding and masking it is correct.  **At 8 wide, bit 0 is
column 7 — a real column — so `& 0xFE` would silently delete the rightmost
column of every bold glyph.**  The result would build, pass a naive eye, and be
wrong.  This is the project's recurring defect class, and it must be fixed with
a test that fails first.

The bit packing itself is already correct for both widths: `1 << (7 - c)` is
byte-based MSB-first, so columns 0..6 map to bits 7..1 at width 7 and columns
0..7 map to bits 7..0 at width 8.  Only the mask and the loop bounds are wrong.

- [ ] **Step 1: Write the failing test**

Create `tools/test-weight.py`:

```python
#!/usr/bin/env python3
"""Prove the widening rule respects the cell width it was given.

The 8-wide cases exist because the rule was written for 7 wide, where bit 0 of
each packed row is BDF padding.  At 8 wide bit 0 is column 7, and a mask that
clears it deletes a real column silently.
"""
import sys
import weight

FAIL = 0


def check(name, got, want):
    global FAIL
    if got != want:
        print(f'FAIL {name}: got {got:#04x}, want {want:#04x}')
        FAIL += 1
    else:
        print(f'ok   {name}')


# ---- 7 wide: the existing behaviour must not change ----------------------
weight.set_width(7)
# columns 0..6 -> bits 7..1.  A stem at column 3 is bit 4 = 0x10.
check('7-wide stem widens left', weight.widen([0x10])[0], 0x30)
# Ink in column 0 (bit 7) has nothing to its left, so it widens right.
check('7-wide col0 widens right', weight.widen([0x80])[0], 0xC0)

# ---- 8 wide: column 7 is real ink and must survive -----------------------
weight.set_width(8)
# A stem at column 7 is bit 0 = 0x01.  It must widen LEFT into column 6,
# giving 0x03 -- and crucially must not be masked away.
check('8-wide col7 survives', weight.widen([0x01])[0], 0x03)
# A full 8-wide row must come back unchanged, not with column 7 cleared.
check('8-wide solid row intact', weight.widen([0xFF])[0], 0xFF)

sys.exit(1 if FAIL else 0)
```

- [ ] **Step 2: Run it and watch it fail**

```bash
cd tools && python3 test-weight.py
```

Expected: the two 8-wide cases FAIL (`set_width` does not exist yet), so the run
errors out on `AttributeError`.  That is the correct first failure.

- [ ] **Step 3: Implement**

In `tools/weight.py`, replace the bare `CELL_W = 7` at line 21 with:

```python
CELL_W = 7


def set_width(w):
    """Set the cell width the rule works at.

    Kept as module state rather than a parameter because embolden.py and
    slant-bold.py both call widen() in loops and there is exactly one width in
    play per run.
    """
    global CELL_W
    CELL_W = w


def _mask():
    """The packed-row bits that are real columns at this width.

    A BDF row is padded to a whole byte, MSB first, so column c is bit 7-c and
    the low 8-CELL_W bits are padding.  At 7 wide that mask is 0xFE; at 8 wide
    it is 0xFF, and using 0xFE there would delete column 7.
    """
    return (0xFF << (8 - CELL_W)) & 0xFF
```

and change line 51 from `out.append(n & 0xFE)` to:

```python
        out.append(n & _mask())
```

Extend the module docstring with a sentence naming the trap, because this
project's history says an undocumented reason gets "fixed" back:

```
The low-bit mask is derived from the width, not the constant 0xFE it used to
be.  At 7 wide bit 0 is BDF row padding; at 8 wide it is column 7, and clearing
it deletes a real column with no visible error.
```

- [ ] **Step 4: Run the test and watch it pass**

```bash
cd tools && python3 test-weight.py
```

Expected: four `ok` lines, exit 0.

- [ ] **Step 5: Prove 7x14 is still byte-identical**

```bash
make clean && make SIZE=7x14 all && sha256sum -c .superpowers/sdd/2026-08-25-8x16/7x14-before.sha256
```

Expected: four `OK` lines.

- [ ] **Step 6: Have `embolden.py` and `slant-bold.py` set the width**

Both take a `SIZE` argument already.  Each must call `weight.set_width(int(SIZE.split('x')[0]))`
before its first `widen()` call.  Re-run Step 5 afterwards; 7x14 must still match.

- [ ] **Step 7: Commit**

```bash
git add tools/weight.py tools/test-weight.py tools/embolden.py tools/slant-bold.py
git commit -m "Derive the emboldening mask from the cell width

At 7 wide bit 0 of a packed row is BDF padding and the constant 0xFE mask was
right.  At 8 wide bit 0 is column 7, so the same mask would have deleted the
rightmost column of every bold glyph silently."
```

### Task 9: The comparison chart

Spec §6.  This is the instrument the user rules with, so it is built before any
drawing begins.

**Files:**
- Create: `tools/build-compare.py`
- Modify: `Makefile` (add a `compare` target to the dispatcher branch)

**Interfaces:**
- Consumes: built `.woff2` for both sizes.
- Produces: `build/compare/index.html`, and `make compare`.

- [ ] **Step 1: Write the generator**

`tools/build-compare.py` emits one self-contained HTML file:

- `@font-face` both sizes' regular `.woff2` from `build/`, referenced by
  relative path, so the page needs nothing installed
- one tile per codepoint in the union target set, each showing the glyph at

### Task 10: Draw the 309 glyphs, in eight batches

**Files (per batch):**
- Create: `glyphs/8x16/regular/<CP>.txt`, one per glyph in the batch

**Interfaces:**
- Consumes: Task 1's bias rule, Task 9's chart.
- Produces: drawings that `build-face.py` picks up with no registration step —
  the filesystem is the index.

**Per-glyph strategy is chosen by class, per spec §4, and recorded:**

**Assign the class mechanically, do not judge it.**  A 7x14 drawing that lights
both column 0 and column 6 is cell-spanning; anything else is letter-box:

```bash
python3 - <<'EOF'
import pathlib
for f in sorted(pathlib.Path('glyphs/7x14/regular').glob('*.txt')):
    rows = [l for l in f.read_text().splitlines()
            if len(l) == 7 and set(l) <= {'#', '.'}]
    cols = {c for r in rows for c, ch in enumerate(r) if ch == '#'}
    if not cols: continue
    print(f.stem, 'cell-spanning' if (0 in cols and 6 in cols) else 'letter-box')
EOF
```

- **cell-spanning** (box drawing, rules, blocks, joining arrows) — **extend to
  fill columns 0..7**.  NEVER pad: a horizontal rule drawn to column 6 leaves
  column 7 blank, so a run of them comes apart at every cell boundary.  That is
  a broken glyph, not a narrow one.
- **letter-box** (punctuation, math, dingbats, standalone arrows) — **widen**
  into the new letter box, columns 1..6 with wide forms reaching 7.  Upstream
  made its own letters wider rather than shifting them, and a padded glyph sits
  visibly thin beside them.
- **solid shapes** (blocks, filled stars) — **scale** x8/7 inside whichever box
  its class gives it.
- **Greek** (batch 10b) — **redraw** against upstream 8x16's own letters.  A
  scaled 7x14 alpha sits wrong beside an 8x16 `a`.  Render the upstream Latin
  alongside while drawing:
  ```bash
  python3 tools/show-glyphs.py upstream/8x16/Tamzen8x16r.bdf U+0061 U+0062 U+006F U+0070 U+0078
  ```

**The file format**, copied exactly — 8 columns and 16 rows, header comment
first, `#` is ink:

```
........

........
........
........
...#....
....#...
.....#..
#######.
.....#..
....#...
...#....
........
........

........
```
